# Controllr V1.5 capability map

Controllr should cover the iPhone’s first-party actions through native APIs and Shortcuts. Start with a permission and module settings screen, Calendar and Reminders, and Messages lookup. Reads should feed results back into the same conversation, so the agent can answer questions such as “What time did Sam say dinner was?” or “Am I free tomorrow at two?”

## Messages and Calendar

**Messages.** On iOS 27, Shortcuts has **Find Message** with a sender filter and a separate **Search in Messages** action. The Find Message definition exposes fields for body, date, subject, and read status. Check that Find Message runs on the paired iPhone 14 Pro and that its output supplies usable body, sender, and timestamp values. Start with recent messages by sender and text search. If the search action only opens Messages on the phone, keep that as an open-search action. User-selected shared or copied text is another input path. A Shortcuts Message automation can handle future arrivals that match its configured trigger. [Apple’s iOS 27 Shortcuts changes](https://support.apple.com/en-us/149045), [Shortcuts action inputs and outputs](https://support.apple.com/guide/shortcuts/navigate-the-action-list-apdc33e4f4da/ios), [Message automation triggers](https://support.apple.com/guide/shortcuts/communication-triggers-apdd711f9dff/ios)

Use the Messages shortcut’s access prompt for lookups. Apple’s native messaging interfaces have narrower roles. An iMessage extension works with the selected conversation context, and TelephonyMessagingKit serves eligible default carrier messaging apps for SMS, MMS, and RCS. [Messages extension](https://developer.apple.com/documentation/messages/msconversation), [Default carrier messaging](https://developer.apple.com/documentation/BundleResources/Entitlements/com.apple.developer.carrier-messaging-app)

**Calendar.** Use EventKit in Controllr to read agendas, check availability, and create, move, or cancel events. Agenda and availability require **full Calendar access**. EventKit also offers a write-only grant for creating events. Give the Calendar modules a default calendar and keep their toggles separate from the existing Reminders modules. [EventKit access levels](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)

## Module settings and permissions

- Give each action an **Enabled** switch in **Modules**. Messages lookup and Send Message are separate switches, as are Add Reminder, Call Contact, and Request Ride. Disabled actions leave the model’s tool list. Controllr checks their state again before executing a prepared action or processing an automation.
- Give applicable actions **Confirmation** settings of **Use default**, **Ask first**, and **Run directly**. Existing defaults carry forward. You can turn off Controllr’s extra prompt for Send Message without changing the default for Call Contact or Request Ride. Apple and third-party prompts still apply.
- Put each action’s options on its settings page. Start with default Calendar and reminder lists, and add choices such as a preferred ride provider when there is a corresponding action.
- Show supported permissions together in **Setup**, including their current access level and the modules that use them. The app currently requests Contacts and Reminders access. Add the Calendar permission descriptions and grant flow first, then Photos, HomeKit, and HealthKit alongside their modules. Shortcut-only actions have their own access prompts. Fetch records on the phone and pass the relevant results to the selected model for the requested turn. [Current app permissions](project.yml), [Shortcuts access prompts](https://support.apple.com/guide/shortcuts/navigate-the-action-list-apdc33e4f4da/ios)

## Actuator extensibility audit

[Action manifests](ControllrCore/Sources/ControllrCore/Actions) already supply tool schemas, inputs, confirmation defaults, execution destinations, and eval cases. Two scratch actions exercised the shared registry and provider-neutral tool interface. A Calendar read passed a fixture result back into the agent loop. A brightness manifest and a small handler produced a new shortcut branch in the generated plist.

| Action type | Current addition path | Work that unlocks the next batch |
| --- | --- | --- |
| Native read | Add a manifest and an executor case that returns a tool result. Add a permission path if the API needs one. | Keep lookup results and auth checks on the existing path. Calendar and Reminders reads fit here. [Native executor](App/NativeExecutor.swift), [Router](ControllrCore/Sources/ControllrCore/Router.swift) |
| Native write | Add a manifest and an executor case. The current router runs native actions while deciding the reply. | Put the confirmation check before execution. For actions that ask first, stage the validated arguments under an action ID, recheck enablement on approval, and consume the approval once. [Router](ControllrCore/Sources/ControllrCore/Router.swift) |
| Shortcut write | Add a manifest and a generator handler. Sign and install a new router build to ship the branch. Confirmation is currently baked into each generated branch. | Use the effective confirmation decision from Controllr at runtime across shortcut actions. Changing a setting should take effect on the next turn without regenerating the router. [Shortcut generator](shortcuts/gen.py) |
| Shortcut read | A handler can run the action. The current callback records completion or cancellation and the shortcut exits. | Return the selected fields as structured text tied to the thread and action IDs. Feed them back as a tool result and resume the existing turn. This is the path for Messages, Apple Notes, and other readable Shortcut actions. [App Intents](App/DecideIntent.swift), [Shortcut generator](shortcuts/gen.py) |
| User-selected shortcut | Current dispatch uses the generated handlers and URL handoffs. | Allow an enabled module to bind to one named shortcut. Verify its input, output, and iPhone prompts. Start with a ride handoff as the exercise. |

Keep each new action to one manifest, one handler, and an eval example. Use a shared handler for repeated forms such as percentage or on/off controls when those actions have the same wiring. Test disabled actions, both confirmation modes, cancellation, and any returned data. Verify on-device permissions and action outcomes before marking an actuator complete. Maintain the same contract across providers. [Provider parity](AGENTS.md)

## First V1.5 builds

1. **Controls in Modules.** Ship enablement, runtime confirmations, and visible permission status. Use Send Message, Call Contact, Request Ride, Add Reminder, and brightness to exercise the shared rules.
2. **Calendar and Reminders.** Add agenda and availability reads, event creation and edits, and reminder listing, completion, and rescheduling.
3. **Messages lookup.** Verify Find Message on the iPhone, wire its result back to Controllr, and check a sender-based lookup followed by a spoken summary. Reuse the result path for Apple Notes and clipboard reads.
4. **More phone actions.** Batch the low-effort device toggles and add a verified Lyft handoff. Pick the next data modules from the map as the same permission and settings patterns prove out.
