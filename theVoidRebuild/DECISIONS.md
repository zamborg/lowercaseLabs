# Decisions

Each one records what was decided, why, and who decided. Anything marked **(default)** was decided by Claude so execution isn't blocked. Zubin can override any of them, and the override goes in this file.

| # | Date | Decision | Why | By |
|---|---|---|---|---|
| D1 | 2026-11-07 | Tags are the four How We Feel quadrants only. 1 dominant tag, plus an optional second | Comparable across people and time. With four values, a third tag carries no information | Zubin (quadrants), Claude (count) |
| D2 | 2026-11-07 | Tagging model: LFM2-1.2B 4-bit, via MLX Swift, schema-constrained. Weights bundled in the app | Mac eval (`eval/tagging/report.md`). Bundling because the first-run download timed out on the phone | Claude |
| D3 | 2026-11-08 | Agents verify by user flows on local rigs, and Zubin is out of the build-and-test loop until TestFlight | Zubin's direction. See [AGENTS.md](AGENTS.md) | Zubin |
| D4 | 2026-11-08 | Rename `Memo` to `Entry` and add `kind`, `visibility`, and model-vs-user provenance for title and tags, **before** any CloudKit schema is deployed to production | CloudKit production schemas can only be extended, never changed. [VISION.md](VISION.md) primitives | Claude |
| D5 | 2026-11-08 | **(default)** A new message is **private** on first use. After that, the capture screen remembers the last choice | Sharing is the riskier mistake. One tap to change it | Claude |
| D6 | 2026-11-08 | **(default)** Lock a recording by **sliding up** past a threshold while holding, like iMessage voice notes. Tap the circle to stop | Familiar gesture. Up is clear of the tab bar | Claude |
| D7 | 2026-11-08 | **(default)** Design for a friend cap of 30. Rig C measures the real limit | Unconfirmed CloudKit sharing limit | Claude |
| D8 | 2026-11-08 | **(default)** No import of old-app messages in v1. Revisit after v1 | It isn't on the critical path. Old data stays in the old app | Claude |
| D9 | 2026-11-08 | Development builds use bundle id `com.lowercaselabs.void` (changed 2026-11-08, see D14), so the rebuild installs **alongside** the old app | Zubin keeps the old app and its data while v1 is unfinished | Claude |
| D10 | 2026-11-08 | **(default, updated)** TestFlight ships under the rebuild's own bundle id, `com.lowercaselabs.void` (D14), as a **new** App Store Connect app with its own name ("The Void" is held by the old record). It installs **alongside** the old app and never touches its data. `app/ship.sh --yes` does the archive and upload; it refuses without `--yes`, and Zubin says when | Reusing the old record would replace the old app and risk its stored data | Claude, pending Zubin's go-ahead per upload |
| D11 | 2026-11-08 | **(default)** New iCloud container, `iCloud.com.lowercaseLabs.void`, not the old app's `iCloud.com.lowercaseLabs.theVoid` | The old container holds the old app's schema and data. A clean schema avoids collisions | Claude |
| D12 | 2026-11-08 | Test seams are launch arguments at the app's edges only (`-fixtureAudio`, `-seed`, `-autotest`). No protocols with one conformer | Vision principle: one implementation per layer | Zubin (principle), Claude (mechanism) |
| D13 | 2026-11-08 | Full v1 (journal **and** Social) is built and running on Zubin's phone before any TestFlight. TestFlight is for distributing to friends, after v1 is tight. *(Supersedes Claude's earlier default of shipping the journal first.)* | Zubin's direction: tighten the whole feature set first | Zubin |
| D14 | 2026-11-08 | Rebuild's bundle id is `com.lowercaselabs.void`, not `com.lowercaselabs.thevoid` | Apple treats bundle ids case-insensitively, so `thevoid` collided with the old app's `com.lowercaseLabs.theVoid` and Xcode refused to register it ("not available"), which blocked the iCloud profile. A distinct id also removes the old-store hazard in D10 if TestFlight uses a new App Store Connect record. D10 stays open for Zubin | Claude |
| D15 | 2026-11-08 | Photo is the second module. An entry is made of **parts** (voice, photo, or both), replacing the single `kind`. A photo part is one back-camera and one front-camera image taken together. The shape must take a third module, or more than one photo, without reshaping `Entry` | Zubin asked for photo-only messages and photos added to voice messages. Parts is the smallest shape where both are the same thing | Zubin (photo mode), Claude (shape) |
| D16 | 2026-11-08 | **(default)** The circle is the shutter. Tap is photo only; touch and hold snaps on touch and then records voice into the same message. Camera is a swipe left from Capture. Snaps from a message's "add photo" attach to it. One photo part per message in v1 | One gesture for both modes keeps capture at one obvious action. Snap on touch keeps the moment you meant | Claude |
| D17 | 2026-11-08 | **(default)** A photo's text for enrichment is Apple's on-device scene labels for both images. A small vision-language model (same MLX stack) is a candidate for the ML loop, judged by evals and the 2 s budget | Labels are cheap, on-device and need no new weights. Whether a VLM is worth ~1 GB more is an eval question, not a guess | Claude |
| D18 | 2026-11-08 | One settings panel, a sheet from a gear in the Void tab: camera (front and back, or back only), show timings, re-tag my messages, about. The app is complete without opening it. *(Narrows the "no settings screens" taste rule in AGENTS.md.)* | Zubin asked for "a settings panel so we can control some things, nothing major". Timings belong there because TestFlight builds can't take launch arguments | Zubin (panel), Claude (contents) |
| D19 | 2026-11-08 | The CloudKit production schema deploy waits until photo mode's shape is in. Photos and audio stay as local files and don't sync in v1 | The production schema can only be extended. Deploying before the parts change would freeze `kind` and force a workaround forever. Cost: dots stay off in TestFlight a little longer | Claude, Zubin approves the deploy |
